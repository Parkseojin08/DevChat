## Auth

### 회원가입

**`POST /auth/signup`**

설명: 새 계정을 생성한다. 토큰은 발급되지 않으며, 가입 후 로그인 페이지로 이동한다.

**인증**: 불필요 (public)

---

**Request Body**

```json
{
  "handle":        "string",   // 필수, 3~20자, 영문/숫자/_, UNIQUE
  "email":         "string",   // 필수, 이메일 형식, UNIQUE
  "name":          "string",   // 필수, 1~50자
  "password":      "string",   // 필수, 8자 이상, 영문+숫자+특수문자
  "birth_date":    "string",   // 필수, YYYY-MM-DD
  "profile_image": "string"    // 선택, 이미지 URL
}
```

---

**Response 201 Created**

```json
{
  "data": {
    "success": true,
    "message": "회원가입을 성공하였습니다."
  }
}
```

---

**Response Errors**

| Status | 메시지 | 발생 조건 |
| --- | --- | --- |
| 400 | "입력 형식이 올바르지 않습니다” | 필드 형식/길이 오류 (errors 필드에 상세) |
| 409 | "현재 사용중인 ID입니다." | 이미 사용 중인 handle |
| 409 | "이미 등록된 email입니다." | 이미 사용 중인 email |

---

### 로그인

**`POST /auth/login`**

설명: 이메일·비밀번호로 인증 후 access·refresh 토큰을 발급한다. 토큰은 HttpOnly 쿠키로 전달된다.

**인증**: 불필요 (public)

---

**Request Body**

```json
{
  "email":    "string",   // 필수
  "password": "string"    // 필수
}
```

---

**Response 200 OK**

```json
{
  "data": {
    "success": true,
    "message": "로그인 성공",
    "user": {
      "id":            "uuid",
      "handle":        "string",
      "name":          "string",
      "profile_image": "string"
    }
  }
}
```

※ `access_token`, `refresh_token`은 응답 본문이 아닌 `Set-Cookie` 헤더로 전달

---

**Response Errors**

| Status | 메시지 | 발생 조건 |
| --- | --- | --- |
| 400 | "이메일과 비밀번호를 입력해주세요." | 필수 필드 누락 |
| 401 | "이메일 또는 비밀번호가 일치하지 않습니다." | 미가입 이메일 또는 비밀번호 불일치 (보안상 둘을 구분하지 않음) |

---

### 친구 관계 삭제 (거절 / 신청 취소 / 친구 끊기)

**`DELETE /friendships/:id`**

설명: 친구 관계를 삭제한다. 상태에 따라 의미가 달라짐:

- pending + 본인이 addressee → **거절**
- pending + 본인이 requester → **신청 취소**
- accepted → **친구 끊기**

**인증**: 필요

---

**Path Params**

```
:id   // friendships.id
```

---

**Response 204 No Content**

(응답 본문 없음)

---

**Response Errors**

| Status | 메시지 | 발생 조건 |
| --- | --- | --- |
| 401 | "인증이 필요합니다." | 로그인 상태 아님 |
| 403 | "권한이 없습니다." | 본인이 requester도 addressee도 아님 |
| 404 | "친구 관계를 찾을 수 없습니다." | 해당 friendship 없음 |

## Messenger

### 채팅방 생성

**`POST /chat-rooms`**

설명: 1:1 또는 그룹 채팅방을 생성한다. 1:1은 `direct_key`로 중복 방 생성을 방지하며, 이미 존재하면 기존 방 정보를 반환한다.

**인증**: 필요

---

**Request Body**

```json
{
  "type":    "string",   // 필수, "direct" | "group"
  "name":    "string",   // 선택 (group일 때 권장)
  "members": ["uuid"]    // 필수, 참여자 id 배열 (본인 제외)
}
```

---

**Response 201 Created** (신규) / **200 OK** (기존 direct 방 반환)

```json
{
  "data": {
    "success": true,
    "message": "채팅방이 생성되었습니다.",
    "room": {
      "id":      "uuid",
      "type":    "direct",
      "name":    "string | null",
      "members": [ "...": "멤버 정보" ]
    }
  }
}
```

---

**Response Errors**

| Status | 메시지 | 발생 조건 |
| --- | --- | --- |
| 400 | "type을 지정해주세요." | type 누락/잘못됨 |
| 400 | "1:1 채팅은 1명, 그룹은 2명 이상의 멤버가 필요합니다." | members 수 부적합 |
| 401 | "인증이 필요합니다." | 로그인 상태 아님 |
| 403 | "친구만 채팅방에 추가할 수 있습니다." | 친구 아닌 사용자 포함 |
| 404 | "존재하지 않는 사용자가 포함되어 있습니다." | members 중 일부 없음 |

### 실시간 메시지 송수신

**`WebSocket (Socket.io)`** — HTTP API 아님

설명: 채팅방에서 실시간으로 메시지를 주고받는다. 텍스트와 미디어 모두 지원.

**인증**: 필요 (소켓 connection 시 토큰 검증)

---

**Client → Server**: 이벤트 `message:send`

```json
{
  "room_id":   "uuid",     // 필수
  "content":   "string",   // 본문 (텍스트)
  "media_url": "string"    // 선택, 첨부 미디어 URL
}
```

※ `content`와 `media_url` 중 최소 하나는 필수

---

**Server → Client**: 이벤트 `message:receive` (같은 채팅방 멤버 전원에게 emit)

```json
{
  "id":         "bigint",
  "room_id":    "uuid",
  "sender_id":  "uuid",
  "content":    "string | null",
  "media_url":  "string | null",
  "created_at": "..."
}
```

---

**에러 이벤트**: `message:error`

| Code | 메시지 | 발생 조건 |
| --- | --- | --- |
| `EMPTY_MESSAGE` | "빈 메시지는 보낼 수 없습니다." | content와 media_url 모두 없음 |
| `NOT_MEMBER` | "채팅방 멤버가 아닙니다." | 본인이 room_members 아님 |
| `ROOM_NOT_FOUND` | "채팅방을 찾을 수 없습니다." | room 없음 |

---
