# Auth

## 회원가입

**DB**: users insert 

설명: 사용자가 서비스를 이용하기 위한 계정을 생성한다. 가입 시 중복 불가능한 고유 아이디를 함께 등록한다.

사전 조건: 비로그인 상태

흐름:

1. 회원가입 페이지에서 정보 입력
2. 가입 버튼 클릭
3. 시스템이 입력값 검증 + 이메일·아이디 중복 확인
4. 비밀번호 해싱 후 DB 저장
5. 로그인 페이지로 이동

입력: 아이디(고유), 이름, 이메일, 비밀번호, 생년월일, 프로필 사진

출력: 가입 완료 메시지 + 로그인 페이지로 이동

예외: 필수 항목 누락 / 이메일 형식 오류 / 이메일 중복 / 아이디 중복 / 아이디 형식 오류 / 비밀번호 정책 위반

## 로그인

**DB**: users select (자격 검증) + users update (refresh_token 저장)

설명: 등록된 사용자가 서비스에 접속하며, **access 및 refresh 토큰을 발급받는다.** access는 클라이언트가 보관하고, refresh는 DB에도 저장하여 재발급 시 검증에 사용한다.

사전 조건: 회원가입 완료, 비로그인 상태

흐름:

1. 이메일·비밀번호 입력
2. 로그인 버튼 클릭
3. 시스템이 이메일로 사용자 조회 + bcrypt로 비밀번호 대조
4. 자격 일치 시 access·refresh 토큰 발급 (refresh는 DB에 저장)
5. 토큰을 클라이언트에 전달 (HttpOnly 쿼키 권장)
6. 메인 화면(뉴스피드)으로 이동

입력: 이메일, 비밀번호

출력: access·refresh 토큰 발급 후 메인 화면 진입

예외: 미가입 이메일 / 비밀번호 불일치 (보안상 둘을 구분하지 않음)

## 로그아웃

**DB**: users update (refresh_token 초기화)

설명: 로그인 상태를 종료한다.

사전 조건: 로그인 상태

흐름:

1. 로그아웃 클릭
2. 토큰 폐기
3. 로그인 페이지로 이동

입력: 없음

출력: 로그인 페이지

## 프로필 편집

**DB**: users update

설명: 본인 프로필 정보를 수정한다. (아이디는 가입 후 변경 불가)

사전 조건: 로그인 상태

흐름:

1. 프로필 페이지 진입
2. 편집 모드 전환
3. 항목 수정 후 저장
4. 시스템이 DB 갱신 (비밀번호 변경 시 해싱 후 저장)

입력: 이름, 자기소개, 프로필 사진(선택), 비밀번호(선택)

출력: 수정된 프로필 화면

예외: 이름 길이 초과, 비밀번호 정책 위반 등 형식 오류

## 토큰 재발급

**DB**: users select + update (refresh_token 검증 후 재발급)

설명: access token 만료 시 refresh token으로 새 토큰을 발급받는다.

사전 조건: 유효한 refresh token 보유

흐름:

1. access token 만료 감지
2. refresh token으로 재발급 요청
3. 시스템이 DB에 저장된 refresh_token과 비교 후 신규 access token 발급 (필요 시 refresh token도 회전)
4. 기존 요청 재시도

입력: refresh token

출력: 새 access token (필요 시 새 refresh token)

예외: 만료/위조된 refresh token → 강제 로그아웃

## 회원 탈퇴

**DB**: users delete (CASCADE → friendships, posts, posts_media, comments, likes, messages, room_members 자동 삭제)

설명: 본인 계정과 관련 데이터를 영구 삭제한다.

사전 조건: 로그인 상태

흐름:

1. 설정에서 "회원 탈퇴" 클릭
2. 비밀번호 재확인
3. 시스템이 계정 삭제 (CASCADE로 연관 데이터 정리)
4. 로그인 페이지로 이동

입력: 비밀번호

출력: 로그인 페이지

예외: 비밀번호 불일치

# Friend

## 사용자 검색

**DB**: users select

설명: 아이디로 다른 사용자를 검색한다.

사전 조건: 로그인 상태

흐름:

1. 검색창에 아이디 입력
2. 시스템이 해당 아이디의 사용자 정보 반환

입력: 아이디

출력: 사용자 정보 (아이디, 이름, 프로필 사진)

예외: 결과 없음 시 "검색 결과 없음"

## 친구 신청

**DB**: friendships insert (status: pending) + notifications insert (friend_request)

설명: 다른 사용자에게 친구 요청을 보낸다

사전 조건: 로그인 상태, 본인이 아니어야 함, 이미 친구가 아니어야 함

흐름:

1. 사용자 프로필에서 "친구 신청" 클릭
2. 시스템이 신청 기록 생성
3. 상대에게 알림

입력: 대상 아이디

출력: "신청 완료" 메시지

예외: 본인에게 신청 / 이미 친구 / 이미 신청 보낸 상태

## 친구 수락 / 거절

**DB**: friendships update (status: accepted) + notifications insert (friend_accepted, 수락 시만) / friendships delete

설명: 받은 친구 신청에 응답한다.

사전 조건: 로그인 상태, 받은 신청 존재

흐름:

1. 받은 친구 신청 목록 조회
2. 수락 또는 거절 클릭
3. 수락 시 친구 관계 성립, 거절 시 신청 삭제

입력: 신청자 "이름(아이디)", 수락/거절 여부

출력: 친구 목록 갱신 또는 신청 삭제

예외: 이미 처리된 신청

## 친구 삭제

**DB**: friendships delete

설명: 기존 친구 관계를 해제한다.

사전 조건: 로그인 상태, 친구 관계 존재

흐름:

1. 친구 목록에서 "삭제" 클릭
2. 확인 후 시스템이 관계 삭제

입력: 친구 아이디

출력: 친구 목록에서 제거

예외: 친구 관계 아님

## 친구 목록 조회

**DB**: friendships select + users join

설명: 본인의 친구 목록을 조회한다.

사전 조건: 로그인 상태

흐름:

1. 친구 페이지 진입
2. 시스템이 친구 목록 반환

입력: 없음

출력: 친구 목록 (아이디, 이름, 프로필 사진)

## 보낸 친구 신청 조회 / 신청 취소

**DB**: friendships select (requester_id = me, status = pending) / friendships delete

설명: 본인이 보낸 대기 중인 친구 신청을 조회하고 철회한다.

사전 조건: 로그인 상태

흐름:

1. 보낸 신청 목록 조회
2. 취소 버튼 클릭
3. 시스템이 신청 기록 삭제

입력: 없음 (조회) / 신청 ID (취소)

출력: 보낸 신청 목록 (취소 시 해당 항목 제거)

예외: 이미 수락·거절된 신청

# Feed

## 게시글 작성

**DB**: posts insert + posts_media insert (미디어 첨부 시)

설명: 본인 피드에 글을 게시한다.

사전 조건: 로그인 상태

흐름:

1. 게시글 작성 화면 진입
2. 본문 입력, 필요 시 사진·미디어 첨부
3. 게시 버튼 클릭
4. 시스템이 저장 후 피드에 노출

입력: 본문 텍스트, 사진·미디어(선택)

출력: 작성된 게시글이 피드에 표시

예외: 빈 내용 입력

## 게시글 수정

**DB**: posts update

설명: 본인이 작성한 게시글의 본문을 수정한다. (사진·미디어는 수정 불가)

사전 조건: 로그인 상태, 본인이 작성한 게시글

흐름:

1. 게시글 메뉴 → 수정 선택
2. 본문 수정 후 저장
3. 시스템이 DB 갱신

입력: 게시글 ID, 수정된 본문 (글만 수정 가능)

출력: 수정된 게시글

예외: 본인 게시글 아님 (권한 없음)

## 게시글 삭제

**DB**: posts delete (CASCADE → posts_media, comments, likes 자동 삭제)

설명: 본인이 작성한 게시글을 삭제한다

사전 조건: 로그인 상태, 본인이 작성한 게시글

흐름:

1. 게시글 메뉴 → 삭제 선택
2. 확인 후 시스템이 삭제

입력: 게시글 ID

출력: 피드에서 제거

예외: 본인 게시글 아님 (권한 없음)

## 뉴스피드 조회

**DB**: posts select (friendships, users, posts_media, likes, comments join)

설명: 본인과 친구들의 게시글을 최신순으로 본다.

사전 조건: 로그인 상태

흐름:

1. 메인 페이지 진입
2. 시스템이 본인 + 친구 게시글을 최신순으로 반환

입력: 없음

출력: 게시글 목록

예외: 게시글 없음 시 안내 메시지

## 프로필 피드 조회

**DB**: posts select (author_id 조건, posts_media join)

설명: 특정 사용자의 게시글을 본다.

사전 조건: 로그인 상태

흐름:

1. 사용자 프로필 페이지 진입
2. 시스템이 해당 사용자의 게시글 반환

입력: 사용자 아이디

출력: 게시글 목록

## 댓글 작성 / 삭제

**DB**: comments insert + notifications insert (post_comment 또는 comment_reply) / comments delete (대댓글은 parent_id 사용)

설명: 게시글에 댓글을 달거나 본인 댓글을 삭제한다.

사전 조건: 로그인 상태

흐름:

- 작성: 게시글 하단 입력창에 내용 작성 → 등록 → 시스템 저장
- 삭제: 본인 댓글의 삭제 버튼 클릭 → 시스템이 삭제

입력: 게시글 ID, (작성 시) 본문

출력: 댓글 목록 갱신

예외: 빈 내용 / 본인 댓글 아님

## 좋아요 / 취소

**DB**: likes insert + notifications insert (post_like) / likes delete (UNIQUE post_id, user_id로 중복 방지)

설명: 게시글에 공감을 표시하거나 취소한다.

사전 조건: 로그인 상태

흐름:

1. 좋아요 버튼 클릭
2. 시스템이 토글 처리 (없으면 추가, 있으면 제거)

입력: 게시글 ID

출력: 좋아요 수 갱신

# Messenger

## 채팅방 생성

**DB**: chat_rooms insert + room_members insert (참여자 수만큼)

설명: 친구와 대화할 채팅방을 만든다 (1:1 또는 그룹).

사전 조건: 로그인 상태, 1:1은 친구 1명, 그룹은 친구 2명 이상

흐름:

1. 채팅 페이지에서 "새 채팅" 클릭
2. 친구 선택
3. 시스템이 채팅방 생성
4. 채팅방으로 이동

입력: 참여자 아이디 목록

출력: 새 채팅방 화면

예외: 본인만 선택 / 친구 아닌 사용자 포함

## 채팅방 목록 조회

**DB**: room_members select + chat_rooms join + messages join (마지막 메시지)

설명: 본인이 속한 채팅방을 목록으로 조회한다.

사전 조건: 로그인 상태

흐름:

1. 채팅 페이지 진입
2. 시스템이 본인 채팅방을 최근 메시지 순으로 반환

입력: 없음

출력: 채팅방 목록 (이름, 마지막 메시지, 시간)

## 실시간 메시지 송수신

**DB**: messages insert (텍스트 본문 또는 media_url)

설명: 채팅방에서 텍스트 또는 미디어(사진 등)를 주고받는다.

사전 조건: 로그인 상태, 채팅방 멤버

흐름:

1. 채팅방 입장
2. 메시지 본문 입력 또는 미디어 첨부 후 전송
3. 시스템이 저장 + [Socket.io](http://Socket.io)로 다른 멤버에게 전송
4. 수신자 화면에 즉시 표시

입력: 메시지 본문 또는 미디어 파일

출력: 채팅방에 메시지 표시

예외: 빈 메시지 (텍스트·미디어 모두 없음) / 채팅방 멤버 아님

## 메시지 내역 조회

**DB**: messages select (room_id 조건, 페이지네이션, is_deleted = true는 placeholder로 반환)

설명: 채팅방의 이전 메시지를 조회한다.

사전 조건: 로그인 상태, 채팅방 멤버

흐름:

1. 채팅방 입장
2. 시스템이 최근 메시지 N개 반환
3. 위로 스크롤 시 이전 메시지 추가 로딩

입력: 채팅방 ID

출력: 메시지 목록

## 메시지 삭제

**DB**: messages update (is_deleted = true)

설명: 본인이 보낸 메시지를 삭제(soft delete)한다. 채팅방에는 "삭제된 메시지입니다"로 표시.

사전 조건: 로그인 상태, 본인이 보낸 메시지

흐름:

1. 메시지 길게 누르기 → "삭제" 선택
2. 확인 후 시스템이 is_deleted = true로 갱신
3. Socket으로 다른 멤버에게 알림
4. 채팅방에 placeholder 표시

입력: 메시지 ID

출력: 채팅방 메시지 갱신

예외: 본인 메시지 아님

## 메시지 읽음 표시

**DB**: room_members update (last_read_message_id)

설명: 메시지를 확인한 사용자를 표시한다.

사전 조건: 로그인 상태, 채팅방 멤버

흐름:

1. 채팅방 입장 시 미확인 메시지를 읽음 처리
2. Socket으로 다른 멤버에게 알림
3. 송신자 화면에 읽음 표시 갱신

입력: 채팅방 ID

출력: 메시지 옆 읽음 표시

## 채팅방 멤버 초대

**DB**: room_members insert + notifications insert (chat_invite, 초대된 사용자별)

설명: 그룹 채팅방에 친구를 추가한다.

사전 조건: 로그인 상태, 본인이 채팅방 멤버, 그룹 채팅방

흐름:

1. 채팅방 설정에서 "멤버 초대" 클릭
2. 친구 선택 후 추가
3. 시스템이 멤버 추가 + 다른 멤버에게 알림

입력: 채팅방 ID, 추가할 사용자 아이디

출력: 채팅방 멤버 목록 갱신

예외: 1:1 채팅방 / 이미 멤버 / 친구 아님

## 채팅방 멤버 목록 조회

**DB**: room_members select + users join

설명: 채팅방 참여자 목록을 조회한다.

사전 조건: 로그인 상태, 채팅방 멤버

흐름:

1. 채팅방 설정 진입
2. 시스템이 멤버 목록 반환

입력: 채팅방 ID

출력: 멤버 목록 (아이디, 이름, 프로필 사진)

## 채팅방 나가기

**DB**: room_members delete

설명: 채팅방에서 본인을 제외한다.

사전 조건: 로그인 상태, 채팅방 멤버

흐름:

1. 채팅방 메뉴에서 "나가기" 클릭
2. 확인 후 시스템이 멤버에서 제거

입력: 채팅방 ID

출력: 채팅방 목록에서 제거

# Notification

## 알림 목록 조회

**DB**: notifications select (user_id 조건, created_at DESC, 페이지네이션)

설명: 본인이 받은 알림을 최신순으로 조회한다.

사전 조건: 로그인 상태

흐름:

1. 알림 페이지 진입 또는 알림 아이콘 클릭
2. 시스템이 본인의 알림 목록을 최신순으로 반환

입력: 없음 (페이지네이션 토큰 선택)

출력: 알림 목록 (type, actor 정보, target 미리보기, is_read, 발생 시각)

## 알림 읽음 처리

**DB**: notifications update (is_read = true)

설명: 알림을 읽음 상태로 변경한다 (개별 또는 일괄).

사전 조건: 로그인 상태

흐름:

- 개별: 알림 클릭 시 해당 알림만 is_read = true
- 일괄: "모두 읽음" 클릭 시 본인의 모든 미읽 알림 갱신

입력: 알림 ID (개별) / 없음 (일괄)

출력: 알림 목록 갱신, 미읽 카운트 감소

## 알림 삭제

**DB**: notifications delete

설명: 본인의 알림을 삭제한다.

사전 조건: 로그인 상태, 본인 알림

흐름:

1. 알림 항목에서 "삭제" 클릭
2. 시스템이 해당 알림 삭제

입력: 알림 ID

출력: 알림 목록에서 제거

예외: 본인 알림 아님 (권한 없음)
